# Contribution discipline

PRs that hit any of these criteria are returned for revision. Run `codi contribute lint` against the local diff to catch them before opening a PR.

## Hard rejection criteria

1. **No edits to generated artifacts** — `.claude/`, `.codex/`, `.cursor/`, `.opencode/`, `.github/copilot/`. These directories are produced by `codi generate` from the source layer. Edit `src/templates/<artifact-type>/<name>/` (maintainer-side) or `.codi/<artifact-type>/<name>/` (consumer-side custom artifacts) instead.

2. **New skill must ship `evals/evals.json`** — every new skill needs at least one eval case so trigger reliability is measurable. Without evals, regressions are invisible.

3. **Skill description ≤ 1500 chars** — long descriptions waste model context on every classification pass and risk selection ambiguity. Move long prose into the skill body or references/.

4. **Workflow yaml declares `chains:` for every non-terminal phase** — `done` and `abandoned` are terminal; every other phase declares which skills chain in. Without `chains:` the phase has no documented agent behaviour.

5. **No direct edits to `.husky/` or `.git/hooks/`** — these are managed by `codi` installers. Edit `src/templates/hooks/` or the install script.

6. **`template.ts` modified → bump `version:`** — version increments surface intent in changelogs and let consumers track skill drift over time.

7. **No `--no-verify` / `SKIPVERIFY` in commit history** — pre-commit hooks exist for a reason. Diagnose the failure; do not bypass.

8. **`docs/` files follow `YYYYMMDD_HHMMSS_[CATEGORY]_slug.md`** — chronological + categorical naming is enforced by `validate-docs.py`.

9. **New skill directory ships `index.ts` barrel** — the skill template loader resolves via the barrel. Missing barrel = the skill is invisible to `codi`.

## How to run the lint

```bash
codi contribute lint --base main
```

Exits 0 if all 9 checks pass on the current diff. Exits 1 with per-check messages otherwise.

## Why this rule exists

Without enforced discipline, the same anti-patterns repeat across PRs and waste reviewer cycles. Surfaced upstream in the contributor's editor, every check becomes a 30-second fix instead of a back-and-forth PR thread.

## When to skip

This rule is opt-in. Install only when:

- Your project receives external contributions (open-source / multi-team).
- Multiple developers edit `.codi/` artifacts and you want consistent PR shape.

Solo projects with a single maintainer can live without it — the cost of a lint runtime is real for low-PR-volume repos.
